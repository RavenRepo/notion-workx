WorX: generate Notion Worker tools from OpenAPI specs

Point WorX at an OpenAPI 3.x spec and get a deployable Notion Worker: a TypeScript project in which every supported endpoint is a worker.tool() that Notion AI agents can call.

View on GitHub Quick start Sponsor 
worx generate --spec https://api.example.com/openapi.json --output ./my-worker
cd ./my-worker && npm install && npm run deploy:create

How it works

1. Parse

WorX reads an OpenAPI 3.0 or 3.1 spec from a URL or a file, resolves local $refs, and detects bearer or API-key auth.

2. Generate

Each supported endpoint becomes a typed worker.tool() with its path, query and header parameters and request body, in a ready-to-build TypeScript worker.

3. Deploy

The generated project deploys with the Notion CLI (ntn). Fill .env, push secrets, and your API is callable from Notion.

FAQ

How do I turn an OpenAPI spec into Notion Worker tools?

Run worx generate --spec <url or path> --output ./worker. WorX writes a TypeScript Notion Worker project in which every supported endpoint becomes a worker.tool(). Deploy it with the Notion CLI.

What is the difference between WorX and the Notion CLI (ntn)?

ntn handles authentication, building, deploying, running and managing workers. WorX is the generation layer on top: it writes the worker code from your OpenAPI spec automatically.

Which OpenAPI features does WorX support?

OpenAPI 3.0 and 3.1 REST APIs with JSON and form-encoded request bodies, path, query and header parameters, bearer and API-key auth, and local $ref resolution. Remote $ref, OAuth2 flows, and multipart, binary or XML-only endpoints are not generated.

What if my API has more endpoints than a Notion Worker allows?

Notion currently caps a worker at 100 capabilities. Split a large API into several workers by generating per tag with --filter.
